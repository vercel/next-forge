Here's how to switch from Neon to [Prisma Postgres](https://www.prisma.io/postgres), a managed PostgreSQL database from the Prisma team. You keep Prisma as the ORM and only replace the Neon driver adapter with the `pg` one.

## 1. Create a new Prisma Postgres database

Create a database in the [Prisma Console](https://console.prisma.io) and copy its connection string. If you just want to try it out, you can also create a temporary database from your terminal. It prints a connection string and a link to claim the database before it is deleted:

```sh title="Terminal"
npx create-db@latest
```

The connection string will look something like this:

```
postgres://<username>:<password>@db.prisma.io:5432/postgres?sslmode=require
```

Keep this connection string handy, you will need it in the next step.

## 2. Update your environment variables

Update your environment variables to use the new Prisma Postgres connection string:

```js title="packages/database/.env"
DATABASE_URL="postgres://<username>:<password>@db.prisma.io:5432/postgres?sslmode=require"
```

```js title="apps/app/.env.local"
DATABASE_URL="postgres://<username>:<password>@db.prisma.io:5432/postgres?sslmode=require"
```

Etcetera.

<Note>
`db.prisma.io` is the direct connection. Prisma Postgres also has a pooled connection, which is the same connection string with the host changed to `pooled.db.prisma.io`. If you deploy to a serverless platform, you can use the pooled host in your apps' environment variables. Always keep the direct host in `packages/database/.env`, as this is the one the Prisma CLI uses to run migrations.
</Note>

## 3. Swap out the required dependencies in `@repo/database`

Uninstall the existing dependencies...

```package-install
npm uninstall @neondatabase/serverless @prisma/adapter-neon ws @types/ws --filter @repo/database
```

...and install the new one. The adapter version should match the version of `@prisma/client` in `packages/database/package.json`:

```package-install
npm install @prisma/adapter-pg@7.4.2 --filter @repo/database
```

## 4. Update the database connection code

Update the database connection code to use the `pg` adapter:

```ts title="packages/database/index.ts {3,9}"
import "server-only";

import { PrismaPg } from "@prisma/adapter-pg";
import { PrismaClient } from "./generated/client";
import { keys } from "./keys";

const globalForPrisma = global as unknown as { prisma: PrismaClient };

const adapter = new PrismaPg({ connectionString: keys().DATABASE_URL });

export const database = globalForPrisma.prisma || new PrismaClient({ adapter });

if (process.env.NODE_ENV !== "production") {
  globalForPrisma.prisma = database;
}

export * from "./generated/client";
```

The Prisma schema and `prisma.config.ts` don't need to change, since Prisma Postgres is a regular PostgreSQL database.

<Note>
`pg` currently logs a warning about SSL modes when the connection string contains `sslmode=require`. It already treats `require` the same as `verify-full`, so you can change the parameter to `sslmode=verify-full` to silence the warning.
</Note>

## 5. Run the migration

Now you can run the migration from the root of your `next-forge` project:

```sh title="Terminal"
bun run migrate
```

If the command fails with `Connection url is empty`, the Prisma CLI is not picking up `packages/database/.env`. Load it at the top of the Prisma config and run the migration again:

```ts title="packages/database/prisma.config.ts {1}"
import "dotenv/config";
import { defineConfig } from "prisma/config";

export default defineConfig({
  schema: "prisma/schema.prisma",
  migrations: {
    path: "prisma/migrations",
  },
  datasource: {
    url: process.env.DATABASE_URL ?? "",
  },
});
```

Your project is now configured to use your Prisma Postgres database for migrations and queries.
