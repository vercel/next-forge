next-forge has pre-built webhook handlers for several key services.

## Payment Events

[Payment events](/docs/packages/payments) are handled in the `POST /webhooks/payments` route in the `api` app. This route constructs the event and then switches on the event type to determine how to process the event.

<Info>To test webhooks locally, we've configured the Stripe CLI to forward webhooks to your local server. This will start automatically when you run `bun dev`.</Info>

## Authentication Events

[Authentication events](/docs/packages/authentication) are handled in the `POST /webhooks/auth` route in the `api` app. 

<Tip>Make sure you enable the webhook events you need in your Clerk project settings.</Tip>

### Local Development

Clerk cannot reach `localhost`, so you need a public URL that forwards to the API app on port 3002. [Clerk recommends ngrok](https://clerk.com/docs/guides/development/webhooks/syncing) with a static domain so the webhook URL stays the same between sessions. `<YOUR_FORWARDING_URL>` is the full `https://` host shown in the ngrok dashboard.

<Steps>
  <Step title="Install ngrok">
    Create an [ngrok](https://ngrok.com/) account and install the CLI. On the ngrok dashboard homepage, follow the setup guide and pick **Static domain**. That gives you a stable forwarding URL you can leave in Clerk.
  </Step>
  <Step title="Start the tunnel">
    With the API app running (`bun dev --filter api`):

    ```sh title="Terminal"
    ngrok http --url=<YOUR_FORWARDING_URL> 3002
    ```
  </Step>
  <Step title="Point Clerk at the API route">
    In the Clerk Dashboard, add an endpoint at `<YOUR_FORWARDING_URL>/webhooks/auth` (for example `https://fawn-two-nominally.ngrok-free.app/webhooks/auth`) and subscribe to the events you need. Copy the **Signing Secret** into `CLERK_WEBHOOK_SECRET` in `apps/api/.env.local`. After the endpoint is saved, open it in the Clerk Dashboard and use **Testing → Send Example** to confirm the local handler receives events.
  </Step>
</Steps>

You can also deploy a staging Vercel project with development environment variables (for example `https://staging-api.example.com/webhooks/auth`) and add that URL in Clerk instead.

## Database Events

One of the most common use cases for inbound webhooks is to notify your application when a database record is created, updated, or deleted. This allows you to react to changes asynchronously, rather than polling the database, cron jobs or other methods.

If you [migrate to Supabase](/docs/migrations/database/supabase), they have an incredibly powerful feature called [Database Webhooks](https://supabase.com/docs/guides/database/webhooks) that helps with this.
